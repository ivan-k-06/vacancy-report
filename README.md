**Vacancy Report** — консольная утилита для анализа выборки вакансий. Получает данные из API Remotive или локального JSON-файла, фильтрует вакансии и сохраняет небольшой отчёт в Markdown.

## Возможности

- Получение удалённых вакансий из API Remotive
- Работа с сохранённым JSON без интернета
- Фильтрация по названию без учёта регистра
- Удаление повторяющихся вакансий по ID
- Подсчёт вакансий по компаниям
- Статистика по категориям, типам занятости и наличию зарплаты
- Список вакансий со ссылками на Remotive
- Сохранение результата в Markdown

## Стек

- `Python 3.12+` 
- `urllib` — HTTP-запросы
- `argparse` — аргументы командной строки
- `json`, `collections` — обработка данных
- `unittest` — тестирование
- `Docker`

## Быстрый старт

### 1. Запуск на примере

В каталоге проекта выполните:

```bash
python3 report.py --input example.json --keyword python --output report.md
```

В [example.json](example.json) находятся демонстрационные данные с вымышленными компаниями. Готовый пример результата — [example-report.md](example-report.md).

### 2. Получение данных из API

```bash
python3 report.py --fetch python --output report.md
```

Ключ и регистрация не нужны. Клиент запрашивает до 100 записей, таймаут — 30 секунд. Это международные удалённые вакансии: используйте английские запросы, например `python`, `backend` или `intern`.

Поиск API идёт по названию и описанию. Дополнительный `--keyword python` оставит только вакансии с Python в названии и может дать пустой результат.

Источник: [Remotive](https://remotive.com/). [Документация API](https://github.com/remotive-com/remote-jobs-api). Данные поступают с задержкой 24 часа. Remotive рекомендует не более четырёх загрузок в день; не запускайте запросы в цикле. Для повторного анализа используйте сохранённый JSON.

При ошибке сети, ограничении API или неправильном формате данных программа выводит сообщение и завершается с кодом `1`.

### 3. Запуск через Docker

```bash
docker build -t vacancy-report .
docker run --rm -v "$PWD:/out" vacancy-report \
  --input example.json --output /out/report.md
```

Отчёт появится в текущем каталоге.

## Аргументы командной строки

| Аргумент | Описание |
|---|---|
| `--input` | Путь к JSON-файлу Remotive с массивом `jobs` |
| `--fetch` | Поисковый запрос для API Remotive |
| `--keyword` | Подстрока для фильтрации названий |
| `--output` | Путь к отчёту, по умолчанию `report.md` |

Нужно указать один источник данных: `--input` или `--fetch`.

## Как это работает

Обработка разбита на небольшие функции:

- `normalize_vacancy` — приводит запись API к внутреннему формату
- `unique_vacancies` — убирает дубликаты
- `select_vacancies` — фильтрует по названию
- `summarize` — считает статистику
- `render_markdown` — собирает текст отчёта

Функции обработки не изменяют исходные данные. Получение данных по сети и чтение файлов выполняются отдельно от расчётов.

Статистика включает количество вакансий, компании, категории, типы занятости и число записей с зарплатой. Зарплаты сохраняются текстом: валюты и периоды выплат различаются, поэтому среднее не рассчитывается. В таблице указаны география и ссылка на исходную вакансию Remotive.

Локальный JSON должен содержать массив `jobs` с полями Remotive: `id`, `title`, `company_name`, `category`, `job_type`, `candidate_required_location`, `salary`, `url`. Старый формат hh.ru с `items` больше не поддерживается. Пример обновлён под новую структуру; компании в нём вымышленные, поэтому ссылки оставлены пустыми.

## Разработка

```bash
python3 -m unittest -v
```

Тесты проверяют фильтрацию, удаление дублей, неизменность исходных данных, группировки, текстовые зарплаты, ссылки на источник и пустую выборку. Запрос к API проверяется с подменой ответа, поэтому для тестов интернет не нужен.
